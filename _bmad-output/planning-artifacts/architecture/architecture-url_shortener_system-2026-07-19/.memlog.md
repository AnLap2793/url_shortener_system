- (direction) Working mode: Coaching path; deliverables: architecture spine plus C4 diagrams; audience: user learning system design and implementation agents.
- (constraint) PRD and UX are binding: root global short-path namespace with tombstones; redirect p95 <=200ms at 100rps/20 connections; dashboard p95 <=2s on 100k events; analytics freshness <=60s; raw click logs 30 days; aggregate retention; email/password plus Google OAuth; WCAG 2.2 AA.
- (decision) Paradigm: frontend plus NestJS API modular backend; binds web/API/worker boundaries and prevents one full-stack application from owning all concerns; user selected for deeper backend architecture learning.
- (decision) Data/auth seed: Drizzle ORM plus Better Auth; binds PostgreSQL access and auth ownership; prevents Prisma/Supabase patterns from coexisting; user selected despite younger/pre-1.0 adoption risk, exact versions pinned.
- (decision) Click capture: core Click Event is durably inserted into PostgreSQL before redirect response; worker enriches and aggregates asynchronously; Redis may accelerate dispatch but is not the source of truth; prevents queue-only event loss and best-effort divergence.
- (decision) Topology: monorepo with React SPA and NestJS API on one same-origin public service; API serves static SPA, /api and root public redirect; worker deploys separately; prevents CORS/cross-origin cookie divergence.
- (decision) Auth integration: mount Better Auth official toNodeHandler on Nest Express adapter before JSON body parser; no community Nest wrapper; prevents divergent auth guards and raw-body handling.
- (decision) Redirect enrichment: detect recognized bots/link previews and derive country/city/device/browser before durable Click Event insert; persist derived fields only, never raw IP; enrichment failure yields unknown and cannot block redirect.
- (decision) Redirect read path: PostgreSQL unique B-tree lookup through bounded connection pool; no Redis in MVP; add cache only after production-like benchmark misses p95 target, preventing stale edit/delete behavior and unnecessary infrastructure.
- (decision) Worker queue: Click Event rows are the durable queue; worker claims with FOR UPDATE SKIP LOCKED plus lease/attempts, LISTEN/NOTIFY only wakes and polling recovers missed notifications; prevents Redis/BullMQ as second source of truth.
- (decision) Deployment baseline: Render Singapore; web/API and worker are separate services, PostgreSQL is co-located in same region/private network; prevents cross-region latency and preserves independent deploy/restart.
- (decision) Aggregation: immutable daily dimensional fact keyed by UTC day, link and full dimension tuple (referrer, country, city, device, browser, utm_source, utm_medium, utm_campaign), UPSERT count; preserves AND filters and Compare Links after raw deletion.
- (decision) Redirect contract: HTTP 302 with Cache-Control no-store; supports mutable destinations and prevents stale browser/CDN redirects after edit/delete.
- (decision) Operations: JSON structured logs with correlation/request ID, health/readiness endpoints, redirect/dashboard latency histograms, worker lag/failure counters and baseline alerts; prevents inability to verify SLO and failure isolation.
- (version) Verified stack candidates: React Router 8.2.0 Data Mode, NestJS 11.1.28, Drizzle 0.45.2, Better Auth 1.6.23, PostgreSQL 18, Render Singapore; exact package versions must be pinned and benchmarked before implementation.
- (decision) Worker failure policy: lease-based claim, exponential-backoff retry up to five attempts, then mark dead-letter and alert; Click Event remains durable for replay; prevents infinite queue poison and silent drop.
- (decision) API contract ownership: NestJS owns DTO runtime validation and OpenAPI document; React consumes generated client types; prevents handwritten frontend/backend schemas diverging.
- (decision) Click durability failure: after active lookup, retry transient PostgreSQL insert briefly within redirect budget; if Click Event cannot commit, return HTTP 503 and do not redirect; preserves FR-11 and SM-8 reconciliation over redirect availability.
